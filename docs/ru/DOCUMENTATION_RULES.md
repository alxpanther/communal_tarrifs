# Правила ведения документации и структуры

> **Язык:** русский — зеркало для чтения человеком.
> Каноническая версия: [../en/DOCUMENTATION_RULES.md](../en/DOCUMENTATION_RULES.md), именно её читают AI-агенты.
> Оба файла обязаны совпадать по смыслу.

Эти правила обязательны для всех, кто трогает репозиторий, — для владельца проекта, для внешних
контрибьюторов и для AI-агентов. Они существуют затем, чтобы правка кода не могла молча сделать
документацию неверной.

---

## 1. Два языка, один смысл

| | Английский (`docs/en/`) | Русский (`docs/ru/`) |
|---|---|---|
| Статус | **Канонический** | Зеркало |
| Аудитория | AI-агенты, внешние контрибьюторы | Владелец проекта |
| Читает ли агент, берясь за задачу | Да, читать нужно только эту версию | Нет |
| Может ли содержать то, чего нет в другой | **Нет** | **Нет** |

Правила:

1. **Сначала пишется английская страница**, затем зеркалится в русскую. Именно английские
   формулировки цитируются в комментариях к коду и в инструкциях для агентов.
2. **Обе версии обязаны совпадать по смыслу** — раздел в раздел, таблица в таблицу, пример в пример.
   Одинаковая структура, одинаковый порядок, одинаковые числа, одинаковые имена файлов. Отличается
   только язык изложения.
3. **Никогда не обновляйте только один язык.** Изменение, попавшее в `docs/en/` без парного
   изменения в `docs/ru/`, считается незавершённым. И наоборот.
4. Каждая страница начинается с языкового блока, как в начале этого файла: какая версия каноническая
   и ссылка на парную.
5. Идентификаторы, имена полей, пути к файлам, JSON-фрагменты, код и команды CLI **не переводятся** в
   обеих версиях. Украинские названия предприятий, названия городов и цитируемые постановления тоже
   сохраняются дословно — это данные, а не текст.
6. `README.md` в корне репозитория остаётся русским: это посадочная страница для человека. Он обязан
   ссылаться на `docs/en/` и `docs/ru/`, и его содержимое не должно им противоречить.

## 2. Что читает AI-агент, прежде чем взяться за задачу

В этом порядке и только английские версии:

1. [`CLAUDE.md`](../../CLAUDE.md) — точка входа.
2. [`PROJECT_STRUCTURE.md`](PROJECT_STRUCTURE.md) — где что лежит.
3. [`ARCHITECTURE.md`](ARCHITECTURE.md) — как работает пайплайн и какие инварианты действуют.
4. Страницу по своей задаче: [`JSON_SPECIFICATION.md`](JSON_SPECIFICATION.md) — для всего, что
   касается выходного формата, [`ADDING_A_COUNTRY.md`](ADDING_A_COUNTRY.md) — для новой страны.

Читать вместо этого `docs/ru/` — ошибка: русские страницы существуют, чтобы владельцу проекта было
удобно, а не как второй источник истины.

## 3. Когда документация обязана обновиться

Документация правится **тем же изменением**, что и код, а не следующим:

| Изменение | Какие страницы обязаны обновиться |
|---|---|
| Появился или исчез файл / каталог | `PROJECT_STRUCTURE.md` (оба языка) |
| Новый этап пайплайна, новая валидация, изменённое поведение при сбое | `ARCHITECTURE.md` |
| Любое изменение выходного JSON — новое поле, новый блок, изменившийся смысл | `JSON_SPECIFICATION.md`, плюс `README.md`, плюс уведомление для Android-стороны. **Сначала требуется согласие владельца проекта**, см. раздел 5 |
| Новый ключ конфигурации в `config/ua/sources.json` | `README.md` и `ARCHITECTURE.md` |
| Добавлена новая страна | `ADDING_A_COUNTRY.md`, `PROJECT_STRUCTURE.md`, `docs/README.md` |
| Новая страница документации | Индекс `docs/README.md`, оба языка |

Пул-реквест, меняющий поведение и не трогающий документацию, считается незавершённым, и его следует
отклонять.

## 4. Правила по структуре

1. **Конфигурация, а не константы.** URL, названия моделей, таймауты, значения тарифов и названия
   стран живут в `config/`. Зашитый в Python URL — дефект, как бы хорошо он ни работал.
2. **Генерируемые файлы руками не правятся.** `docs/tariffs_<cc>.json`,
   `assets/tariffs_<cc>_default.json` и обе копии `tariffs_index.json` перезаписываются при каждом
   запуске; фиксируйте значения через `manual_override`.
3. **Временная работа — в `tmp/`** в корне репозитория, и папка удаляется по завершении задачи.
   Отладочные дампы, результаты замеров и черновые скрипты не должны оставаться в `src/`, `docs/` и
   в корне репозитория.
4. **Одна ответственность на модуль.** Доставка в Telegram живёт в `common/telegram_notifier.py`,
   логика тарифов — в пайплайне страны. Не размазывайте побочные эффекты ввода-вывода по коду.
5. **Одна реализация общего поведения.** Всё, что две страны делают одинаково, живёт в
   `src/common/`. Вторая копия в fetcher'е другой страны — дефект, даже если она правильная.
6. **Комментарии в коде — на английском.** Независимо от языка общения и языка русской документации.
7. **`docs/` — это веб-корень.** Всё, что туда закоммичено, публикуется через GitHub Pages. Никаких
   секретов и черновиков.

## 5. Замороженные контракты

Две вещи в этом репозитории являются контрактом с Android-приложением, и нарушение любой из них
ломает уже установленные у пользователей приложения:

**Схема выходного JSON.** Переименование, удаление или смена типа существующего поля запрещены без
предварительного согласия владельца проекта. Добавлять новое поле можно, но владельцу нужно сообщить
об этом явно, потому что на стороне приложения потребуется парная правка. Каждое добавление
описывается в `JSON_SPECIFICATION.md` тем же изменением.

**Значения `city_code`.** Однажды назначенный код постоянен: приложение хранит его как сохранённый
выбор пользователя. `config/ua/city_registry.json` обязан быть закоммичен, а коды правятся только
осознанно и вместе с миграцией на стороне приложения.

## 6. Стиль страницы документации

* Отвечайте на вопрос «что это и что мне с этим делать», а не «что делает строка 42».
* Для перечислений по полям и по файлам используйте таблицы.
* Каждое утверждение о поведении должно быть правдой для кода в его нынешнем виде. Если вы описываете
  запланированное, а не реализованное, помечайте это явно.
* Ссылайтесь на функции и файлы по именам, а не по номерам строк — номера устаревают мгновенно.
* Сохраняйте разобранные примеры: реальный блок `manual_override` или реальный фрагмент JSON стоит
  страницы описаний.
