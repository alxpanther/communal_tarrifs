# Структура проекта

> **Язык:** русский — зеркало для чтения человеком.
> Каноническая версия: [../en/PROJECT_STRUCTURE.md](../en/PROJECT_STRUCTURE.md), именно её читают AI-агенты.
> Оба файла обязаны совпадать по смыслу; см. [DOCUMENTATION_RULES.md](DOCUMENTATION_RULES.md).

Этот репозиторий — **генератор данных**, а не приложение. Он собирает официальные тарифы ЖКХ,
валидирует их и публикует один JSON-файл, который читает Android-приложение. Кода приложения здесь
нет.

## 2. За что отвечает каждая часть

### `config/` — единственный вход, редактируемый руками

| Файл | Кто ведёт | Правила |
|---|---|---|
| `sources.json` | Владелец проекта | Все URL, которые трогает пайплайн, лежат здесь. **Ни одного URL в Python-коде.** Здесь же `settings` (выбор модели Gemini, таймаут HTTP) и `manual_override` (значения, накладываемые поверх собранных). |
| `city_registry.json` | Пайплайн + владелец | Сопоставляет название поставщика ровно в том написании, что на сайте-источнике, постоянному `city_code`. Новые поставщики дописываются автоматически; **уже назначенный `city_code` не переписывается никогда**, потому что Android-приложение хранит его как выбор пользователя. Секция `suppliers` — водоканалы, `heat_suppliers` — поставщики тепла (общая для горячей воды и отопления). |

### `src/` — пайплайн

| Файл | Ответственность |
|---|---|
| `tariffs_fetcher.py` | Всё: загрузка конфига, HTTP-запросы, разбор HTML, вызовы LLM, валидация, назначение `city_code`, ручные переопределения, сверка источников, запись обоих выходных файлов. Пошаговый разбор — в [ARCHITECTURE.md](ARCHITECTURE.md). |
| `telegram_notifier.py` | Единственное место, которое общается с Telegram. Деградирует мягко: без токена печатает сообщение в stdout и возвращает `False`, так что пайплайн никогда не падает из-за уведомлений. |

### Генерируемые файлы — руками не править

`assets/tariffs_ua_default.json` и `docs/tariffs_ua.json` побайтово одинаковы и **перезаписываются
при каждом запуске**. Любая ручная правка молча теряется на следующем прогоне. Чтобы зафиксировать
значение, используйте `manual_override` в `config/sources.json` (раздел README «Ручное
переопределение тарифов»).

### `docs/` — документация *и* веб-корень

У этой папки двойная роль: в ней лежит документация и она же публикуется через GitHub Pages и
объявлена как каталог статики в `wrangler.toml`. Следствия:

* `docs/tariffs_ua.json` обязан оставаться в корне `docs/` — от этого зависит опубликованный URL.
* Markdown-файлы внутри `docs/` тоже публикуются. Само по себе это безвредно, но секретов и
  черновиков здесь быть не должно.

## 3. Поток данных между частями

```
config/sources.json ─┐
                     ├─> src/tariffs_fetcher.py ─┬─> docs/tariffs_ua.json ──> GitHub Pages
config/city_registry ┘        │                  │                       └──> Cloudflare R2
        ▲                     │                  └─> assets/tariffs_ua_default.json ──> сборка Android
        └── новые поставщики ─┘
                              └─> src/telegram_notifier.py ──> Telegram (алерты, расхождения)
```

Опубликованные URL (оба отдают один и тот же файл):

* `https://tarrifs.foleks.com/ua/tariffs_ua.json` — Cloudflare R2
* `https://alxpanther.github.io/communal_tarrifs/tariffs_ua.json` — GitHub Pages

## 4. Переменные окружения

Локально читаются из `.env` (через `python-dotenv`), в CI — из секретов GitHub Actions.

| Переменная | Обязательна | Для чего |
|---|---|---|
| `GEMINI_API_KEY` | да | Вызовы извлечения и Search Grounding |
| `GEMINI_MODEL` | нет | Фиксирует конкретную модель, перекрывает `settings` в `sources.json` |
| `TELEGRAM_BOT_TOKEN` | нет | Уведомления; без него сообщения уходят в stdout |
| `TELEGRAM_CHAT_ID` | нет | То же |
| `CLOUDFLARE_API_TOKEN` | только для деплоя | `wrangler r2 object put` |
| `CLOUDFLARE_ACCOUNT_ID` | только для деплоя | То же |

`.env` в `.gitignore` и должен там оставаться.

## 5. Куда класть новое

| Вы добавляете | Кладите сюда |
|---|---|
| URL источника, название модели, таймаут | `config/sources.json` — никогда не в Python |
| Принудительное значение тарифа | `config/sources.json` → `manual_override` |
| Пайплайн новой страны | См. [ADDING_A_COUNTRY.md](ADDING_A_COUNTRY.md) — отдельный модуль в `src/`, свой конфиг, свой выходной файл |
| Новую страницу документации | В `docs/en/` **и** `docs/ru/`, плюс строку в `docs/README.md` — см. [DOCUMENTATION_RULES.md](DOCUMENTATION_RULES.md) |
| Одноразовый скрипт или дамп для отладки | Папка `tmp/` в корне репозитория, удаляемая по завершении. Ничему временному не место в `src/`, `docs/` и в корне репозитория |
| Изменение схемы выходного JSON | Ничего, пока владелец проекта не согласовал. Схема — контракт с Android-приложением, см. [DOCUMENTATION_RULES.md](DOCUMENTATION_RULES.md), раздел «Замороженные контракты» |
